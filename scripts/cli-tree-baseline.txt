                                                                                                    
 Usage: kizen [OPTIONS] COMMAND [ARGS]...                                                           
                                                                                                    
 Kizen Builder — drive a Kizen environment from the conversation. The working directory's           
 .kizen/profile pin selects the environment. Read commands are safe. Mutation verbs (create/update) 
 build a plan from live state, show it, and confirm before applying; --dry-run previews without     
 applying.                                                                                          
                                                                                                    
╭─ Options ────────────────────────────────────────────────────────────────────────────────────────╮
│ --profile,--env       -p,-e      <str>  Profile to target. Normally the working directory's      │
│                                         .kizen/profile pin decides; this overrides it, but a     │
│                                         pinned directory still refuses a profile whose           │
│                                         business_id doesn't match the pin.                       │
│ --version             -V                Show the installed version and exit.                     │
│ --install-completion                    Install completion for the current shell.                │
│ --show-completion                       Show completion for the current shell, to copy it or     │
│                                         customize the installation.                              │
│ --help                                  Show this message and exit.                              │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
╭─ Commands ───────────────────────────────────────────────────────────────────────────────────────╮
│ apply             Apply a saved plan (the JSON a mutation verb emits with --dry-run --json).     │
│ upgrade           Update this CLI in place.                                                      │
│ init              Set up this directory as a Kizen environment folder.                           │
│ docs              Read the documentation that ships with this CLI.                               │
│ envs              Discover and inspect configured envs.                                          │
│ objects           Read objects, custom and built-in; create, update, and delete custom objects.  │
│ dashboards        Read, create, and update dashboards and homepages.                             │
│ layouts           Read and update record layouts for a custom object.                            │
│ records           Read individual records from a custom object.                                  │
│ filters           Look up valid --filter operators (no live env needed).                         │
│ team              Look up team members.                                                          │
│ roles             Read and manage roles.                                                         │
│ permissions       Read and manage permission groups + the permissions catalog.                   │
│ automations       Read, create, update, and run automations.                                     │
│ messages          Email templates and automation-scoped messages — the content                   │
│                   notify_member_via_email steps reference (see `kizen docs show                  │
│                   email-templates`). Kizen's builder UI 'select email' picker only recognizes a  │
│                   message as selected when it's seeded from a real template; that's what         │
│                   `create` does.                                                                 │
│ fields            Create and update fields on custom objects.                                    │
│ categories        Create and update field categories on custom objects.                          │
│ filter-groups     Per-object saved filters (segments): /filter-groups.                           │
│ quick-filters     Per-object quick-filter chips: /quick-filters.                                 │
│ columns           Per-object saved column layouts: /columns.                                     │
│ activities        Read and edit activity types (loggable definitions), their fields, and read    │
│                   logged/scheduled instances. An 'activity' here is the type/template — logging  │
│                   and scheduling instances happen in the Kizen UI, not here.                     │
│ forms             Create, read, update, and delete forms, their fields, and their visual page    │
│                   layout (form_ui).                                                              │
│ surveys           Create, read, update, and delete surveys, their fields, and their visual page  │
│                   layout (form_ui).                                                              │
│ smart-connectors  Build, inspect, and iterate on smart connectors. Read verbs                    │
│                   (list/get/executions/scripts/events/metadata) are safe. The local SQL loop is  │
│                   pull → run → push: `pull` builds a working directory, `run` executes           │
│                   connector.sql against embedded ClickHouse (needs the 'connectors' extra),      │
│                   `push` writes the SQL back to the draft and can publish it live. Building one  │
│                   from scratch runs create → set-input → (SQL loop) → generate-sample → push     │
│                   --publish → configure-flow → activate → start-flow.                            │
│ code              Unit-test code_step scripts in the live sandbox via `POST                      │
│                   /api/coderunner/run`. Runs standalone — no automation, no record, nothing      │
│                   created in the env — so it's confirm-free like `automations start`.            │

 Usage: team search [OPTIONS] {name}                                                                
                                                                                                    
 Search team members by name or email.                                                              
                                                                                                    
 Returns id, full_name, email, and title. The id is what you pass to                                
 owner/assigned_to fields and scheduled activity employee_id.                                       
                                                                                                    
╭─ Arguments ──────────────────────────────────────────────────────────────────────────────────────╮
│ *    name      <str>  Name or email fragment to search for. [required]                           │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
╭─ Options ────────────────────────────────────────────────────────────────────────────────────────╮
│ --limit   -n      <int>  Max results to return. [default: 10]                                    │
│ --output  -o      <str>  Output format: table (default), json, or csv.                           │
│ --json                   Alias for --output json.                                                │
│ --help                   Show this message and exit.                                             │

 Usage: upgrade [OPTIONS]

 shape. For a checkout that means pulling *and* re-syncing dependencies, so
